# XML Sitemap Generator (xsmg)

Отдаёт Google News sitemap с самыми новыми записями, опубликованными за
последние 48 часов. Одна лента, один адрес, без настроек.

Версия 1.5.8. Требуется WordPress 7.0+, PHP 8.0+.

## Установка

1. Скопировать каталог `news-sitemap-generator` в `wp-content/plugins/`.
2. Активировать плагин в разделе «Плагины».
3. Открыть `https://example.com/news-sitemap.xml` — должна открыться XML-лента.

Настроек в админке нет. Плагин не создаёт таблиц в базе: готовая лента
хранится в одном транзиенте, проверка обновлений держит до двух транзиентов
(результат и метка ошибки), плюс три служебные опции (последняя структура ЧПУ,
время чистки кэша, время запуска cron). При удалении плагина удаляются все его
опции и транзиенты.

## Адрес ленты

Ровно один адрес:

```
https://example.com/news-sitemap.xml
```

- Параметров нет. `?xsmg_news_sitemap=2`, `/news-sitemap2.xml` и другие
  похожие адреса — обычные запросы WordPress: плагин на них не реагирует, ленту
  не строит и кэш не создаёт.
- Лента отдаётся и с ЧПУ, и без: плагин сравнивает путь запроса с
  `/news-sitemap.xml`. Без ЧПУ запрос должен доходить до WordPress (стандартное
  правило фронт-контроллера у веб-сервера); если сервер сам отвечает 404,
  плагин этот запрос не увидит.
- Ответ: код `200`, `Content-Type: application/xml; charset=utf-8`,
  `Last-Modified` и `Cache-Control: public, max-age=1800`.

## Какие записи попадают в карту

Карта (sitemap) строится по записям за последние 48 часов. Окно считается от
момента запроса: запись старше 48 часов исчезает из карты при следующей
генерации.

| Что | Как |
|---|---|
| Окно | последние 48 часов |
| Статус | только `publish`; черновики, приватные и запланированные не попадают |
| Тип | только записи (`post`), страницы и произвольные типы — нет |
| Пароль | записи с паролем исключаются |
| Порядок | по дате публикации, новые сверху |
| Объём | не больше 1000 URL, один файл |
| Язык | основной подтег локали сайта: `ru-RU` → `ru`; китайские локали сохраняют регион (`zh-cn`, `zh-tw`) |

**Пагинации нет.** Google News разрешает не больше 1000 URL на файл, поэтому
лента всегда одна. Если за 48 часов опубликовано больше 1000 записей, в ленту
попадут только 1000 самых новых; более старые записи этого окна в неё не
войдут.

### Yoast SEO

Если Yoast SEO активен, в карту попадают только записи, у которых тип схемы
статьи — `NewsArticle` (мета `_yoast_wpseo_schema_article_type`). Записи с
другим типом (`Article`, `BlogPosting` и т. п.) и записи без явно
выставленного типа схемы в карту не попадают: мета у них не хранится.

Если Yoast SEO не активен, этот фильтр не применяется: в карту попадают все
подходящие записи за 48 часов, независимо от схемы.

**Если карта пустая**, проверьте у свежей записи тип схемы статьи в Yoast SEO
(в боковой панели редактора, вкладка «Схема»): пока там не `NewsArticle`,
запись в карту не попадёт. После изменения типа сохраните запись — кэш
сбросится сразу; без сохранения изменения появятся в течение 30 минут.

Плагин сам предупреждает о такой ситуации: в админке показывается уведомление
«в окне 48 часов нет записей с типом схемы NewsArticle — проверьте тип схемы у
свежих записей», а при пустой генерации в лог пишется одна строка. Настроек
для этого нет.

## Поля ленты

Для каждой записи выводятся:

- `<loc>` — постоянная ссылка;
- `<news:news>` → `<news:publication>` с названием сайта и языком;
- `<news:publication_date>` — дата публикации в ISO 8601;
- `<news:title>` — заголовок без HTML-тегов.

Заголовки и названия экранируются как XML-текст: `&`, `<`, `>`, кавычки не
ломают документ, `]]>` не может закрыть CDATA (CDATA не используется),
эмодзи сохраняются, управляющие символы вырезаются.

## Кэш и сброс

Готовая лента кэшируется одним транзиентом на 30 минут. Дополнительно
браузеру и прокси разрешено кэшировать ответ на 1800 секунд.

Кэш сбрасывается сразу, когда меняется запись, которая может быть в ленте:

- сохранение записи (`save_post`);
- удаление записи (`before_delete_post`);
- перемещение в корзину (`trashed_post`).

Записи старше 48 часов кэш не сбрасывают: их в ленте уже нет. Раз в сутки
WP-Cron около 03:00 по часовому поясу сайта удаляет устаревшие записи кэша,
если их срок почему-то не истёк.

## Проверка в Google Search Console

1. Подтвердить право собственности на сайт.
2. Открыть «Файлы Sitemap» и добавить `news-sitemap.xml` (или полный адрес
   `https://example.com/news-sitemap.xml`).
3. Убедиться, что статус — «Успешно», код ответа 200, а в списке найденных
   URL есть свежие записи.

Сама лента не включает сайт в Google News: для показа в новостях сайт должен
соответствовать требованиям Google News и быть принят в программу. Sitemap
лишь помогает Google быстрее находить свежие материалы.

Если Search Console показывает 404, проверьте, что плагин активен, а запрос
`/news-sitemap.xml` действительно доходит до WordPress (не блокируется
правилами сервера или кэшем).

## Обновления

Плагин обновляется штатным механизмом WordPress из репозитория
[Gnoztis/news-sitemap-generator](https://github.com/Gnoztis/news-sitemap-generator):
берётся более новая версия из последнего релиза GitHub и тегов вида `vX.Y.Z`
или `X.Y.Z`; при равенстве версий выигрывает релиз — у него есть описание
изменений. Архив — zip-ассет релиза или zipball GitHub. Пакет принимается
только по `https` и только с доменов GitHub.

Проверка кэшируется на 6 часов, ошибка — на 15 минут. Если проверка не
удалась, причина видна в строке плагина и на экране «Плагины», например
«проверка не удалась: 403 (лимит GitHub API)». Кнопка «Проверить обновления»
сбрасывает кэш и игнорирует паузу после ошибки.

Без токена GitHub разрешает 60 запросов в час на IP, и этот лимит общий для
всех плагинов на хостинге. Необязательный fine-grained personal access token
с правом **Contents: Read** поднимает лимит до 5000 запросов в час:

```php
define( 'XSMG_GITHUB_TOKEN', 'github_pat_…' );
```

в `wp-config.php` или фильтр `xsmg_github_token`. Токену нужен только доступ
на чтение публичного репозитория, и он нигде не выводится. Без токена плагин
работает как раньше, но при исчерпании лимита проверка покажет ошибку 403 до
следующей успешной проверки.

## Удаление

Деактивация снимает задачу WP-Cron и очищает кэш. Удаление плагина удаляет
опции `xsmg_*` и транзиенты плагина (лента, диагностика Yoast, проверка
обновлений); чужие опции и транзиенты не затрагиваются.
